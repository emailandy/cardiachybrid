# Resus QC Operational Runbook

This runbook describes standard operating procedures for maintaining, testing, and troubleshooting the `resus_qc` data pipeline and REDCap integration.

---

## 1. End-to-End Workflow: Adding a REDCap Variable

To add a new REDCap variable to the `video_review` instrument and integrate it across the pipeline:

1. **Edit the Data Dictionary**:
   - Update `dictionary/` CSV files with the new field specification (ensuring valid REDCap field type, validation, and choices).
2. **Rehash the Dictionary**:
   - Run `bash scripts/hash_dict.sh` to update `dict_version.txt` with the new SHA-256 hash.
3. **Map the Field in the Registry**:
   - Add the field entry to `mapping/registry.yaml` under the appropriate section or repeating group, specifying its rule (`gate_3way`, `first_of`, etc.), `source_class`, and `difficulty` tier.
   - For 2-choice radio fields using `gate_3way`, add `no_utd_code: abstain`.
4. **Rebuild Code & Coverage Manifest**:
   - Run `python -m codegen.emit_python` to regenerate `generated/redcap_fields.py` and `generated/submission.py`.
   - Run `python -m codegen.emit_manifest` to regenerate `generated/coverage_manifest.json`.
5. **Extend the Anchor Card**:
   - Update or create the corresponding clinical event anchor card in `prompts/anchors/` (ensuring it passes `scripts/check_anchors.py`).
6. **Run Unit & Coverage Tests**:
   - Execute `pytest -m "not (integration or network)"` and `bash scripts/check_invariants.sh` to verify schema spine integrity and invariant compliance.
7. **Deploy BigQuery Schema**:
   - Apply BigQuery schema migration (`D07`) so that new export columns are reflected in raw staging and core fact tables.
8. **Execute Live Round-Trip Verification**:
   - With `RESUS_ALLOW_NETWORK=1` and credentials configured, run `pytest -v -m "integration and network" tests/test_roundtrip.py` against a scratch project to verify end-to-end REDCap import and export byte-equality.

## 2. BigQuery Audit Views Reference

The BigQuery audit layer defines five operational views (`D07`). When any view returns rows, it signals a specific pipeline or data quality condition requiring intervention:

| Audit View | What It Means When It Returns Rows | Recommended Action |
| :--- | :--- | :--- |
| **`audit_unmapped_fields`** | Identifies REDCap dictionary fields that carry data but are left unmapped (`source_class == 'UNMAPPED'`) in `mapping/registry.yaml`. | Add a declarative rule in `mapping/registry.yaml` or explicitly assign `source_class: HUMAN_ONLY` / `ROSTER_JOIN` / `NEVER_AI`. |
| **`audit_schema_drift`** | Detects mismatches between columns generated by `codegen` and the actual BigQuery destination table schema. | Re-run Terraform / schema migration scripts to synchronize BigQuery table columns with `EXPORT_COLUMNS`. |
| **`audit_utd_anomalies`** | Surfaces records where the rate of `'3'` (`Unable to determine`) emissions for a field or case drops below the field's `expected_utd_floor`. | Investigate sensor/channel degradation (`_CHANNEL_ISSUES`) or inspect if model confidence is masking missing visual/audio data. |
| **`audit_routing_queue`** | Lists all `FieldValue` rows flagged for human-in-the-loop (HITL) review along with their routing reason (`low confidence`, `TEAM (Q-006)`, `truncated group`, etc.). | Clinical review queue: present these fields in the human adjudication UI for manual verification before Complete sign-off. |
| **`audit_temporal_spread`** | Flags clinical timestamps where the multi-agent ensemble spread exceeds the policy threshold (`spread > 3.0s`). | Review audio/visual evidence across ensemble agents to resolve timestamp divergence on clinical events. |

## 3. Managing Routing Thresholds and Difficulty Tiers

- **Difficulty Tiers**: Each field in `mapping/registry.yaml` is assigned a difficulty tier (`LOW`, `MEDIUM`, or `HIGH`).
- **Thresholds**: Defined in `config/routing.yaml` (`LOW=0.80`, `MEDIUM=0.85`, `HIGH=0.90`). Any populated field whose ensemble confidence falls below its difficulty threshold routes to human review as `'low confidence'`.
- **Branching Non-Applicability**: Optional or repeating-group fields whose REDCap branching logic evaluates to `False` (`branching_satisfied == False`) are skipped by the router (`'branching_not_satisfied'`) and never queue for review.

## 4. Troubleshooting CI & Schema Verification Failures

- **Manifest Diff Warning (`::warning`)**: Occurs when `generated/coverage_manifest.json` changes without edits to `dictionary/` or `mapping/`. Requires PR reviewer check to confirm intentional codegen output changes.
- **Determinism Failure**: Codegen produced different output across two consecutive invocations. Check for unordered set/dict iteration in Python emitters.
- **Line Count / String Literal Lints**: `reducer/engine.py` must remain under 500 lines and contain zero double-quoted REDCap field literals (`I2`). Use single quotes for symbol splitting (`.split('___')[0]`).
- **Invariant Failure (`check_invariants.sh`)**: Verify dictionary hash, check binary Yes/No values (`I3`), and confirm zero schema coercion in validators (`I6`).

## 5. What is NOT yet Verified

Anyone inheriting this repository should be aware of the following unverified components and operational dependencies:

- **No Sensors (`S1–S7`)**: Physical sensor streaming and hardware channel ingestion pipelines are unverified in Phase 1.
- **No Gold Set**: A ground-truth clinical validation dataset has not yet been evaluated against the ensemble pipeline.
- **No Clinical Review of the 39 Anchor Cards (`Q-009`)**: All 39 anchor cards in `prompts/anchors/` pass structural syntax and field-reference validation (`scripts/check_anchors.py`), but their clinical prompt text has not undergone affirmative clinical lead sign-off.
- **No Live REDCap Round-Trip (`Q-014`)**: Acceptance tests in `tests/test_roundtrip.py` are skipped offline. Definitive proof that our 1,891 export columns match REDCap's server dictionary requires a live scratch REDCap project and API token.
- **TEAM Ratings Uncalibrated (`Q-006`)**: All 12 subjective resuscitation team performance rating fields route unconditionally to HITL review until inter-rater reliability (`ICC >= 0.75`) is established in production.
